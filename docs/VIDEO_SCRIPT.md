# 演示视频脚本（5–8 分钟）

> 要求：MP4 / ≥1080p / 普通话讲解 / 可配字幕 / 含项目介绍、核心功能演示、AI 技术亮点。
> 目标时长 **6 分 30 秒**。旁白按 4 字/秒估算，全文约 1560 字。

## 一、录制前准备

| 项 | 做法 |
|---|---|
| 分辨率 | 浏览器全屏 1920×1080，页面缩放 100%，隐藏书签栏（Ctrl+Shift+B） |
| 干净桌面 | 关闭微信/QQ 通知、退出无关标签页 |
| 预热 | 提前 1 分钟启动服务并问一个问题，确保 BGE-M3 已加载、不进冷启动 |
| 演示数据 | 库内保留 9 篇论文（含 v1/v7、扫描件、GPT-3），索引已建好 |
| 鼠标 | 移动放慢，点击前停顿 0.5 秒，方便观众跟上 |
| 录制 | OBS 或 Win+G，码率 ≥ 8000 kbps，30 fps |

## 二、分镜表

| 镜 | 时长 | 画面操作 | 旁白（逐字稿） |
|---|---|---|---|
| 0 | 0:00–0:12 | 黑底标题卡：SciLoom 智研织机 / 基于大模型与 Agent 架构的全流程科研助手 | （无旁白，配轻音乐） |
| 1 | 0:12–0:50 | 文献台空态或库列表，缓慢滚动 | 科研里最耗时间的不是读论文，而是找论文、核对细节、以及确认自己没记错。通用聊天机器人能聊，但它会流畅地编造超参数和参考文献——而科研对幻觉是零容忍的。SciLoom 要解决的就是这件事：把一篇论文从下载到写成综述，织成一条每一步都能回到原文的链路。 |
| 2 | 0:50–1:55 | 拖入 `1706.03762v7.pdf` → 解析完成；再拖入 `v1.pdf` → 右下角弹出重复预警卡；点开版本差异 | 先看文献管理。系统基于正文内容做语义去重，不看文件名。我先入库第七版，再入库第一版——右下角立刻弹出预警：判定为同一工作的不同版本，正文重合度 90.5%，并建议保留库中更新的 v7。点开修订差异，它按章节对齐，告诉我结论部分改动最大，参考文献从 36 条增加到 40 条。 |
| 3 | 1:55–2:45 | 切到「章节树」展开两级；切到「表格」看 Table 1；再打开扫描件那篇 | 解析不是简单抽文本。标题树由字号、编号和位置共同判定，表格结构化还原，公式单独标记。更关键的是扫描件：这篇 PDF 没有文本层，系统走 OCR 识别，再把像素坐标按比例反算回 PDF 坐标——所以扫描件和原生 PDF 在上层看来是同一种东西。 |
| 4 | 2:45–3:55 | 右侧问答面板提问「训练用了多少块 GPU、什么型号」；展示流式回答与 `[c2]` 芯片；点击芯片跳到原文页；再问一个证据不足的问题 | 这是抗幻觉问答。回答是流式吐出来的，每一句后面都有引用编号，点一下就跳到原文那一页——因为解析阶段就存了字符级坐标。注意第二个问题的答案：它直接说"现有材料不足以回答"，只说明型号是 V100，没给数量。它没有编，这正是我们要的。 |
| 5 | 3:55–4:35 | 切到「对照」页签，左右双栏；拖动左栏，右栏跟着滚 | 中文读者可以直接进入对照模式。公式和参考文献不翻译，引用编号原样保留。两侧同步不是按滚动比例，而是按段落对齐——行高不一样，比例同步会越读越偏。 |
| 6 | 4:35–5:25 | 点左侧「引用图谱」；悬停节点；右侧综述文本；点一个基石节点跳回文档 | 把库里九篇论文放在一起，系统会连出引用网络，用 PageRank 和中介中心性划分角色：Adam、Attention、Layer Normalization 是基石，RoBERTa 是衍生工作。右侧这段综述不是模型编的，是从图的结构翻译出来的——谁被引几次、时间跨度、有没有环，都能对上。 |
| 7 | 5:25–6:00 | 「检索发现」页搜索 RAG，展示相关性分数与代码标记；点一次「下钻入库」 | 检索结果不是照搬 arXiv 排序，而是按"与本地库的相关性、有没有开源代码、时效"重排，并给出理由。看到合适的，一键下钻：下载、解析、去重、入库、建索引，全自动。 |
| 8 | 6:00–6:45 | 「写作 Copilot」生成框架（引用列表在右侧）；切「数据图表」上传 CSV，展示双面板图与图注；切「架构图脚本」看 Mermaid | 写作环节同样有约束：参考文献只能从库内取，编号越界会被剔除。数据图表会根据数据形状自动选图——这里 BLEU 和参数量差了两个数量级，它自动拆成上下两个子图，并在图注里写明原因，图注里的峰值和趋势都是从同一份数据算出来的。 |
| 9 | 6:45–7:15 | 架构图（文档中的分层图）；快速切三个画面：空格 bug 前后对比、检索评测表、引用校验正则 | 技术上最值得说的是三个坑：第一，LaTeX PDF 的空格会被单独输出成文本片段，早期实现把它当噪声过滤，整句粘成一坨，检索命中率从 5/6 掉到 2/6；第二，BM25 与向量平行融合在跨语言下反而更差，改成"稠密召回加短名单重排"后回到 6/6；第三，引用校验正则要求四位编号，而证据编号是 c1，这道防线从上线起就没生效过。 |
| 10 | 7:15–7:30 | 回到文献台全景 + 片尾信息卡 | SciLoom 不是把 AI 塞进阅读器，而是把"可追溯"做成了产品结构。代码、文档与在线演示地址见 README。谢谢观看。 |

> 上表时长合计约 7 分 30 秒，若需压到 6 分半，优先压缩第 3 镜与第 9 镜。

## 三、后期

1. **字幕**：按本稿逐句对齐，字号 28–32 px，白字深色描边，放画面下方 1/6 处。
2. **重点标注**：在引用芯片跳转、双面板图、图谱节点处加 1 秒方框高亮。
3. **片头片尾**：用文档封面的配色（深青 + 氧化红 + 纸白），保持与产品一致。
4. **导出**：H.264 / 1920×1080 / 30fps / 码率 8–10 Mbps，文件名 `SciLoom-演示视频.mp4`。

## 五、提词器与素材

**提词器**：浏览器打开 [`assets/video/teleprompter.html`](../assets/video/teleprompter.html)，
全屏后按空格开始滚动，`←` `→` 调速。字号按 1080p 调过，放副屏或手机照着念就行。

**片头 / 片尾卡**（1920×1080，直接拖进剪辑软件）：

- `assets/video/title-card.png`
- `assets/video/end-card.png`

**录屏流水线（可选）**：`apps/web/scripts/record-sample.mjs` 用 CDP 截屏流 + ffmpeg
把真实操作录成 1080p MP4（产物 `assets/video/sample.mp4`，9.5 秒）。不想手动录屏的，
可以把分镜翻译成该脚本的动作序列自动生成画面轨，再用提词器配音。

> 注意：CDP 截屏流只在画面变化时出帧，静止画面靠持有上一帧补齐，
> 滚动、打字这类连续动作会比实时录制略顿。正式录制仍建议用 OBS 实时录。
